# APP 与 Frontend 功能差异整理

## 对比范围

- APP：`mini_program_app/pages.json`、`mini_program_app/api`
- 网页版：`Frontend/src/router/index.js`、`Frontend/src/views`、`Frontend/src/api`
- 对比日期：2026-07-29

本文只记录“APP 已经存在，但 Frontend 没有或没有形成完整业务闭环”的能力。

## 结论

Frontend 当前主要覆盖首页、地图、活动、会议入口、AI 助手、AI 工具展示、课程详情、个人中心、考试和简历。

APP 的业务覆盖明显更完整，主要差距集中在：

1. 个性化学习闭环
2. 校园二手市集
3. 校园论坛与社交互动
4. 真实消息与交易通知
5. AI 工具实际生成流程
6. 会议、课表、场馆等深层业务页面

## 重点功能说明

### 1. 个性化学习

APP 已有：

- Python 个性化学习首页
- 学习画像问题提交
- 学习路径查询与重新规划
- 精准推荐及交互记录
- 知识图谱
- 专项学习资源流式生成
- 单项资源失败重试
- 路径节点开始、完成
- 智能体协作链路

Frontend 没有学习相关路由，也没有 `learning` API 模块。这部分适合优先迁移，因为后端能力已经存在，主要工作集中在桌面交互与接口接入。

### 2. 校园二手市集

APP 已形成完整链路：

- 商品分类、列表、搜索、热门商品和详情
- 发布、上架、下架
- 收藏与收藏列表
- 买卖双方聊天
- 预订、确认、完成和取消交易
- 我的发布、我的购买、交易记录
- 浏览记录、系统通知、交易通知

Frontend 没有相关路由、页面和 API。考虑到项目定位是校园二手平台，这应当是网页版最高优先级业务模块之一。

### 3. 校园论坛

APP 已支持帖子、话题、评论、点赞、收藏、举报、关注关系和用户主页。Frontend 当前没有论坛入口，也没有论坛 API。

建议网页版采用三栏结构：话题导航、帖子流、热门话题/关注动态，桌面空间利用率会比直接复制移动端页面更高。

### 4. 消息与通知

APP 的消息能力包括：

- 分类消息列表
- 未读数量
- 单条和批量已读
- 实时消息票据
- 市集聊天未读
- 交易通知
- 公告详情

Frontend 虽然有消息页面，但没有对应 `message` API 模块，部分内容是页面内静态数据。应统一接入真实消息服务。

### 5. AI 工具

Frontend 的 AI 工具页展示了试卷、PPT、思维导图、架构图和流程图等卡片，但点击逻辑主要停留在选择展示；APP 已有对应生成、预览、历史或下载页面。

因此这类能力不是“没有入口”，而是“缺少可完成任务的生成闭环”。

### 6. 地图与校园设施

Frontend 地图已有点位展示、地点详情、校园助手和浏览器本地失物招领演示，但 APP 进一步提供：

- 导航记录和到达/取消状态
- 附近设施统计
- 餐厅、档口、菜品和菜品评价
- 运动场详情
- 教学楼详情
- 宿舍详情与宿舍选择

网页版可保留地图作为统一入口，采用右侧抽屉承载设施详情，再跳转复杂业务页面。

## 推荐实施顺序

1. Python 学习工作台、知识图谱、专项资源和智能体链路
2. 校园二手市集与真实消息
3. 校园论坛
4. AI 工具生成闭环
5. 会议、课表和设施详情
6. 优惠、签到、公告、成绩与账户设置
