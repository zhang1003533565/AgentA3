# 开源与第三方合规流程

## 发布结论

当前状态：**有条件阻断**。代码和本地测试可以继续，但在下列 P0 项关闭前，不应把提交包描述为“许可证已全部确认”：

1. `wordpapergenerate` 模板材料缺少来源、作者和授权记录。
2. PyMuPDF 需要在 AGPL-3.0-or-later 与 Artifex 商业许可之间确定真实许可路径并履行义务。
3. Tencent COS SDK 与 AppFrontend `compressorjs` 的实际许可证证据未随仓库冻结；后者还缺锁文件。
4. 只完成了直接依赖清单，最终镜像的传递依赖 SBOM 与完整许可证文本包尚未生成。

## 决策规则

- 团队代码：没有全体权利人明确决定时，不新增仓库级开源许可证。
- 第三方源码/模板：必须保留来源 URL、作者、版本、许可证/授权、修改说明和哈希。
- 依赖：版本必须来自锁文件/BOM/精确 requirements，不用“最新版”描述。
- 强互惠或网络互惠许可证：进入镜像前由发布负责人记录采用理由、分发形态、源代码提供方式和许可证文本。
- 专有 SDK/API：记录产品条款、账号主体、用途和数据流，不把服务可访问误写成可再分发。
- AI 生成内容：不能替代第三方来源证明，也不能给未知材料自动生成许可证。

## 当前组件审查

### PyMuPDF

`ai-servers/app/rag/document_conversion/pdf_converter.py` 直接导入 `fitz`，因此不是“仅安装未使用”。最终负责人必须二选一：

- 按 AGPL-3.0-or-later 路径准备相应源代码、修改说明、许可证文本和网络交互义务评估；或
- 取得与提交/部署范围匹配的 Artifex 商业许可。

仅在 NOTICE 中写一行名称不能替代这些义务。

### pdf2docx

仓库代码没有导入 `pdf2docx`，其本地包元数据声明 GPLv3。本次已从 `requirements.txt` 删除；不得在没有真实用途与许可评估的情况下重新加入。

### wordpapergenerate 模板

当前仅能确认 `AppBackend/src/main/resources/exam-paper-template` 由外部参考工程迁移，不能确认权利。来源负责人需补：

- 原始仓库/交付地址和获取日期；
- 作者/权利人；
- commit/tag 或文件版本；
- LICENSE 或书面授权；
- 原始与提交文件 SHA-256；
- 团队修改说明。

如果无法补齐，使用团队重新制作且可证明来源的模板替换。

## 最终发布流程

1. 从最终冻结 SHA 创建干净工作区。
2. 运行 Maven、pip、npm 和容器 SBOM/许可证扫描，保存工具版本与原始输出。
3. 对每个 `NOASSERTION`、自定义许可证、AGPL/GPL/SSPL/RSAL 和专有组件人工审查。
4. 将许可证正文、NOTICE、源码提供说明放入提交包显著位置。
5. 对 `THIRD_PARTY_NOTICES.md` 与镜像内实际组件做差异检查。
6. 运行 secret/PII 扫描，不把扫描日志中的秘密再次提交。
7. 由一名非编写者复核来源表和 AI Coding 披露。
8. 记录发布负责人、复核人、日期、最终 Git SHA、镜像摘要和未解决例外。
