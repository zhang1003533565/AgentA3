# AI Coding 使用说明

## 使用工具

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| OpenAI Codex（Desktop/本地工作区代理） | 本次会话未暴露可核验客户端版本 | 仓库分析、实现、测试、文档与验证 |
| oh-my-codex（OMX）协作层 | 本次会话未冻结发行版本 | 计划、子任务协调、提交规范与质量流程 |

未记录的版本不会在文档中猜测。最终提交时应补充客户端/插件实际版本截图或命令输出。

## AI 辅助范围

本轮 AI 参与了：

- 根据 A3 赛题与已批准设计计划梳理缺口；
- Java/Python/AppWeb/AppFrontend 的局部实现、回归测试和质量门禁；
- 五服务 Compose、内部服务令牌、环境地址与 CI；
- Python 课程知识清单校验、30 题事实评测与 5×50 压测脚本；
- 安全、隐私、第三方组件和提交文档草拟；
- 本地命令执行、测试结果读取和 Git 提交整理。

AI 未替团队决定第三方授权、知识库来源权、学生数据使用权、模型服务条款或比赛最终陈述。

## 人工约束与关键决策

用户明确要求：

- 以 Python 课程为主线，使用已经放入知识库的课程资料；
- 全面补齐赛题能力，但不删除或堵死现有校园功能；
- 两天内完成可提交版本；
- 不伪造知识库统计、评测指标、性能数据或功能完成状态。

团队仍需人工确认：

- MaxKB 源文件、版本、分段与许可证；
- 模型和智能体绑定；
- 演示账号、截图、PPT、视频与口径；
- 安全联系人、隐私策略、依赖许可与最终提交授权。

## 审查与测试

AI 生成或修改的代码必须经过可执行验证。本轮已执行的主要门禁包括：

- AppBackend Maven 全套测试；
- ai-servers pytest（一次完整门禁为 264 passed）；
- AppWeb Node 测试、ESLint 与 Vite production build；
- AppFrontend Node 测试；
- Compose 配置校验；
- 知识清单、30 题分布与压测计划校验。

测试通过不等于外部 MaxKB/模型、容器下载、真机 UI 或第三方许可已验证。相关结果必须分别标记 `not_run`、`needs_export` 或待办。

## 敏感数据规则

- 不向 AI 提供真实 API Key、JWT、内部 capability、学生密码、个人成绩或不可再分发课程原文。
- 工具输出、日志和提交信息不得包含秘密。
- 需要真实联调时使用专用演示账号和最小权限凭据，完成后轮换。
- AI 不负责判断材料是否已脱敏；提交前由人工执行 secret/PII 扫描和视觉检查。

本轮发布资产没有使用真实外部 MaxKB/模型凭据，也没有运行在线事实评测或性能压测；相应 artifact 明确为 `not_run`。

## 已知限制

- AI 可能遗漏业务边界、误判许可证或生成表面通过的测试，因此必须由非编写者复核高风险变更。
- 本次工具没有联网查询第三方最新条款；许可证只依据仓库与本地包元数据，未确认项已显式阻断。
- 事实题标准答案是评测基准，不代表已与真实 MaxKB 来源完成证据映射。
- 评测脚本的自动关键词评分只作预检，解释题最终结论需要人工双人复核。
- PPT、PDF、视频和冻结演示包不在本说明所记录的已完成范围内。
