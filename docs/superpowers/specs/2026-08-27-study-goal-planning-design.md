# 学习计划拆解升级设计

**目标**：把现有“AI 拆成平级任务并勾选”的功能升级为可编辑、可排程、可按今日执行的学习计划工作流。

## 范围

本轮只改学习计划功能，不改变 AI 创作入口、已有鉴权、历史找回和原有文本/CSV/XLSX 输入通道。用户仍然可以先生成预览，再确认入库。

纳入本轮：

- 输入计划开始日期和目标日期，日期为空时使用今天作为开始日期且不设置目标日期。
- 预览页支持编辑目标标题、描述、任务名称、阶段、预计天数、优先级，支持新增、删除和上下移动任务。
- 入库时按任务预计天数顺序生成 planned_start_date / planned_end_date。
- 任务支持 pending、in_progress、blocked、skipped、completed 五种状态；完成状态仍由 Checkbox 控制。
- 任务支持 0-100 的部分完成度，目标进度按 estimated_days 加权，继续返回已完成数量和剩余数量。
- 执行页增加“今日”筛选，展示当前日期覆盖且未完成的任务。
- 任务支持延期一天，并同步顺延同一计划中后续未完成任务的排程。
- 计划列表显示日期范围、进度和当前状态。

暂不纳入：提醒推送、日历第三方同步、复杂依赖图、学习资源推荐、自动复习算法、计划删除/归档。

## 数据模型

`study_goal` 增加：

- `start_date DATE NULL`
- `target_date DATE NULL`

`study_task` 增加：

- `planned_start_date DATE NULL`
- `planned_end_date DATE NULL`
- `progress_percent INT NOT NULL DEFAULT 0`

任务状态仅允许 `pending / in_progress / blocked / skipped / completed`。当 `progress_percent=100` 时状态为 `completed`；当 Checkbox 取消时回到 `in_progress`（已有进度）或 `pending`。

目标进度使用预计天数加权：

`sum(task.estimated_days * task.progress_percent) / sum(task.estimated_days)`，四舍五入到整数。

## 用户流程

1. 入口进入独立页面。
2. 用户选择文本或文件输入，二者互斥；输入开始日期和目标日期。
3. AI 生成目标与任务预览。
4. 用户直接修正预览内容，必要时新增、删除、排序任务。
5. 确认创建后展示计划日期范围、目标进度和今日任务。
6. 用户完成、部分完成、阻塞、跳过或延期任务。
7. 用户从历史列表找回计划，继续今日执行或重新排程。

## 兼容与错误处理

- 旧计划没有日期时仍可打开，显示“未排期”，任务仍可勾选。
- 旧任务没有 `progress_percent` 时按完成状态映射为 0 或 100。
- 输入日期反向、任务为空、预计天数非法时在前端阻止提交，后端再次校验。
- AI 失败、保存失败、加载详情失败时保留当前输入/预览，并提供明确的重试入口。
- 文件内容超过后端上限时拒绝并告知用户，不再静默截断。

## 验收标准

- 文本、CSV、XLSX 三通道仍能生成预览并入库。
- 预览中的编辑、新增、删除、排序结果会原样入库。
- 目标进度不再按任务数量等权计算，部分完成会反映到进度。
- 今日筛选只显示日期覆盖今天且未完成的任务。
- 延期会改变任务日期并顺延后续未完成任务。
- 旧数据无日期时可正常打开。
- 非本人目标和任务仍返回 404。
- 既有学习计划回归测试保持通过。
