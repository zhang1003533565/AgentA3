# 题库智能生成设计

## 目标

在管理后台“题库管理”分组中新增“题库生成”菜单。管理员可以上传 DOCX、TXT，或直接粘贴文本，选择一种题型后，由 Java 后端根据 AI 模块中的可配置映射调用对应智能体。生成结果必须先预览、编辑和校验，确认后才导入当前 `exam_question` 题库。

## 已确认范围

- 一次任务只生成一种题型。
- 支持现有五种标准题型：`single_choice`、`multiple_choice`、`true_false`、`fill_blank`、`short_answer`。
- 最大题量为可选项。填写时表示生成上限，不要求智能体凑数；不填写时由智能体按有效知识点自动决定数量。
- DOCX 提取标题、正文和表格文本，暂不识别图片。
- TXT 和粘贴内容按纯文本处理。
- 生成后先预览、编辑、删除和校验，再由管理员显式导入题库。
- 题型与智能体的对应关系在“智能体设置”中维护，不允许在生成页面、Java 服务或 Python 调用代码中写死。
- 未配置有效智能体映射时禁止生成，不回退到 Leader。
- 直接在当前 `master` 分支修改，不创建功能分支或工作树。

## 导航与页面

“题库管理”菜单顺序调整为：

1. 题库
2. 题库生成
3. 试卷生成
4. 生成的试卷

“题库生成”使用独立路由 `/question-bank/generate`，页面采用三阶段流程，但保持在同一路由内：

1. **生成设置**：选择来源、题型、可选最大题量、可选难度和来源标题。
2. **智能生成**：显示实际使用的智能体、模型、解析后的材料摘要和调用进度。
3. **预览与导入**：显示生成数量、缺失信息、警告和逐题编辑区；校验通过后才能导入。

页面支持三种互斥输入方式：

- DOCX 文件上传；
- TXT 文件上传；
- 文本粘贴。

切换输入方式时清空上一种方式的临时内容，避免同时提交多个来源。DOCX 页面明确提示“提取正文、标题和表格，暂不识别图片”。

## 智能体映射配置

在现有“智能体设置”页面新增“题库生成映射”卡片。每个标准题型配置一个智能体，配置保存到现有系统配置表，键名为：

```text
ai.question-generation.agent.single_choice
ai.question-generation.agent.multiple_choice
ai.question-generation.agent.true_false
ai.question-generation.agent.fill_blank
ai.question-generation.agent.short_answer
```

下拉选项来自 `/api/ai/rag/agents` 返回的实时智能体目录，不限定智能体名称。每行显示题型、已选智能体、启用状态和模型绑定状态。

配置有效需要同时满足：

- 映射值非空；
- 智能体仍存在；
- 智能体处于启用状态；
- 智能体可以解析为一个已测试可用的默认模型。

配置页面允许保存尚未启用或尚未绑定模型的智能体，但明确显示红色状态；题库生成接口会拒绝使用无效配置。这样管理员可以先完成配置，再逐步启用模型，同时不会发生隐式回退。

## 后端架构

新增题库生成控制器和服务，Java 后端是唯一编排入口。前端不得自行根据配置拼接智能体调用。

### 控制器

新增 `/api/exam/question-generation` 接口组：

- `GET /options`：返回五种题型的映射状态、智能体展示信息和当前可用性。
- `POST /generate`：接收 multipart 请求，输入为来源类型、可选文件或文本、题型、最大题量、难度和来源标题，返回生成草稿及校验结果，不落库。

接口要求已登录管理员。生成接口只返回普通 JSON，不保存原始上传文件。

### 文件解析

文件解析封装成独立组件：

- TXT 使用 UTF-8 读取，并移除 UTF-8 BOM；无法按 UTF-8 解码时返回明确错误。
- DOCX 使用项目已有 Apache POI 依赖读取段落和表格，按文档顺序输出可读文本。
- 拒绝 `.doc`、压缩包伪装、空文件和超过配置上限的文件。
- DOCX 必须能被 `XWPFDocument` 正常打开，否则按非法或损坏文件处理。
- 解析结果去除无意义空行，但保留段落和表格单元格之间的边界。

默认限制为单文件 10 MiB、解析后文本 200,000 个字符；限制通过 Spring 配置项声明，便于部署时调整。

### 配置解析与智能体调用

生成服务按所选题型读取 `ai.question-generation.agent.<type>`。服务随后复用现有智能体开关、模型绑定和 Python AI 代理能力，验证映射和模型后构造调用请求。

请求包含：

- 原始材料文本；
- 目标题型及其标准 JSON 结构要求；
- 可选最大题量；
- 可选难度；
- 禁止脱离材料、重复出题和为了凑数降低质量的约束；
- `sourceScene=question_generation` 等追踪元数据。

最大题量只作为上限。若返回题数超过上限，后端视为结果不合规并拒绝返回可导入草稿，不静默截断。

### 生成结果标准化

智能体必须返回现有题库顶层结构：

```json
{
  "questions": [],
  "missingInfo": []
}
```

Java 后端从智能体响应中解析 JSON，并通过现有 `ExamQuestionService.review(request, expectedType)` 校验。返回给前端的数据包括：

- 实际智能体名称和角色；
- 实际生成数量；
- 最大题量；
- `questions`；
- `missingInfo`；
- `valid`、`issues` 和 `warnings`；
- 来源标题和原文件名。

所有题目必须与所选题型一致。结构错误、题型混入、空结果或超过最大题量时均不得标记为可导入。

## 预览、编辑与导入

前端将每道题以可编辑卡片展示，并根据题型提供对应字段：

- 通用字段：题干、分值、难度、知识点、标签、解析；
- 单选/多选：选项和正确选项；
- 判断：正确或错误；
- 填空：空位与各空答案；
- 简答：参考答案与答案要点。

管理员可以删除不合格题目。编辑和删除后，前端调用现有 `/api/exam/questions/review?expectedType=...` 重新校验。存在错误时禁用“导入当前题库”；警告不阻止导入，但必须可见。

最终导入继续使用现有 `/api/exam/questions/import`，并提交：

- `sourceAgent`：后端本次实际调用的智能体；
- `sourceTitle`：用户填写的标题，否则使用原文件名或“粘贴文本生成”；
- `sourceScene`：固定为 `question_generation`。

前端不得允许用户修改 `sourceAgent`。导入成功后显示导入数量，并提供“查看题库”和“继续生成”操作。

## 错误处理

- 映射缺失：提示“该题型未配置生成智能体，请到智能体设置完成映射”。
- 智能体停用：提示具体智能体名称，并禁止生成。
- 模型不可用：提示该智能体未绑定已测试模型。
- 文件类型或内容非法：在调用智能体前返回 400。
- AI 服务失败：保留后端可诊断日志，前端显示安全、明确的失败原因。
- AI 输出不是题库 JSON：返回结构错误和响应摘要，不导入、不尝试猜测修复。
- 生成数量为零：展示 `missingInfo`，不允许进入导入动作。
- 页面重复点击：生成按钮进入 loading 状态，阻止同一页面并发提交。

日志记录题型、智能体、材料字符数、最大题量、实际题量、耗时和结果状态，不记录完整材料、认证令牌或完整智能体答案。

## 测试策略

### 后端

- 系统配置映射：五种题型、缺失映射、未知智能体、停用智能体、无模型绑定。
- TXT 解析：UTF-8、BOM、空文件、非法编码、大小限制。
- DOCX 解析：段落、标题、表格、损坏文件、伪装扩展名、大小限制。
- 生成编排：正确智能体选择、可选最大题量、自动题量、难度透传、超量拒绝。
- 结果校验：空结果、非法 JSON、混入题型、现有题库结构错误和合法结果。
- 控制器：管理员权限、multipart 参数校验和错误响应。

### 前端

- 菜单和路由包含“题库生成”。
- 智能体设置可以读取、编辑和保存五种映射。
- 无效映射时题型不可生成并显示原因。
- 三种输入方式互斥，文件限制和必填校验正确。
- 最大题量为空或有值时请求结构正确。
- 生成结果可以编辑、删除、重新校验和导入。
- 校验失败时导入按钮不可用，导入成功后跳转操作正确。

### 完整验证

- 后端相关单元测试与控制器测试；
- 前端 Node 测试、ESLint 和生产构建；
- 使用真实 TXT、含标题/正文/表格的 DOCX 完成生成到导入的管理后台烟雾测试；
- 确认导入题目出现在当前题库，并可被现有试卷生成模块选中。

## 非目标

- 不识别 DOCX 图片、公式或手写内容。
- 不支持 `.doc`、PDF、PPTX 或多个文件批量上传。
- 不在一次任务中混合生成多种题型。
- 不增加自动导入、定时生成或生成历史表。
- 不在本功能中创建或训练新的智能体；只消费 AI 模块已提供的智能体目录和模型配置。
