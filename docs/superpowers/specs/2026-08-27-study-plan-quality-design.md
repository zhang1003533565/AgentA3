# 学习计划拆解质量优化设计

## 目标

将“学习计划拆解”从生成少量主题任务，优化为生成可理解、可排期、可勾选、可验收的任务树，并让历史计划可以安全补全细分任务。

## 已确认的问题

1. Python 内部接口的 `TaskPlan` 响应模型没有声明 `subtasks`，导致 AI 已生成的细分任务在 FastAPI 响应校验阶段被过滤。
2. 提示词允许多日大任务返回空细分任务，模型可以合法输出“学习 C++ 基础语法”这种不可直接执行的条目。
3. 当前解析器只做字段清洗，不检查任务粒度、子任务覆盖、完成标准和天数一致性。
4. 已保存的旧计划没有修复入口，页面只能继续展示没有细分步骤的旧数据。

## 产品规则

### 任务层级

```text
目标
└── 阶段任务（组织内容，不直接勾选）
    ├── 执行步骤（一次具体行动，可勾选）
    ├── 练习/产出（有明确结果，可勾选）
    └── 验收/复盘（有完成标准，可勾选）
```

- 父任务是阶段或里程碑，不作为执行 Checkbox。
- 预计超过 1 天的父任务必须有 2~6 个细分任务。
- 细分任务必须是一次具体学习行动、练习或产出，不能只是重复父任务标题。
- 细分任务应包含完成标准或产出物描述。
- 子任务预计天数之和必须等于父任务工作量。
- 原始输入已经是明确的一天原子任务时，可以保留为无子任务的兼容叶子任务。

### 生成质量门禁

- 提示词明确要求父任务与叶子任务的职责边界。
- Python 解析层保留嵌套字段，并执行结构、重复、粒度、描述和天数校验。
- 首次输出不合格时，使用同一模型进行一次定向修正。
- 修正后仍不合格时拒绝进入保存流程，返回可理解的错误信息。
- 任何失败都不修改用户已有计划。

### 历史计划补全

- 只对没有任何细分任务的旧计划显示“AI 补全细分任务”。
- 补全前二次确认，说明会新增执行步骤并重新计算排期。
- 后端只补全缺失的父任务，不覆盖已有细分任务和完成进度。
- 补全完成后返回完整详情，前端原地刷新。

## 页面体验

- 预览页显示“大任务数、执行步骤数、预计天数”，并以阶段分组展示细分任务。
- 执行页显示阶段标题和阶段完成比例，Checkbox 只属于细分任务。
- 全部/剩余/已完成/今日统计只统计叶子执行任务。
- 旧计划没有细分任务时显示状态提示和补全按钮，不把父任务伪装成完整执行步骤。

## 接口与数据

- 保持现有 `Goal -> StudyTask -> StudySubtask` 表结构，不新增第三层。
- 修复内部 Python 响应契约，使 `subtasks` 正常传递到 Java。
- 新增 Java 的旧计划补全接口，使用现有归属校验和 AI 代理链路。
- 删除计划继续使用现有的归属校验和级联删除逻辑。

## 验收标准

1. 以“30天学会 C++”为例，预览至少出现多个阶段和每阶段多个可执行细分步骤。
2. AI 返回父任务但没有必要细分时，系统不会静默保存为低质量计划。
3. AI 返回的子任务在 Python -> Java -> UniApp 链路中不丢失。
4. 旧的父任务计划可以通过补全入口生成并保存细分任务。
5. 细分任务勾选、状态、延期和进度聚合继续正确。
6. 归属越权、删除和历史找回回归不受影响。
