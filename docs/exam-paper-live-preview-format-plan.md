# 试卷生成体验优化方案

## 总体目标

这套试卷生成系统的主流程已经比较完整：试卷信息、选题、页面格式、真实预览、确认保存。接下来优化重点按用户流程重新整理为三段：

1. 试卷信息与选题
2. 页面格式
3. 预览与确认

核心原则：

- 评分规则放在选题阶段，不放在页面格式里。
- 页面格式只处理纸张、方向、栏数、页眉学生信息栏、字号等版式问题。
- 预览页允许继续调格式，并能直接重新生成预览。
- 失败时必须给用户可见反馈。
- Windows 下 LibreOffice 依赖要更稳定。

## 1. 试卷信息与选题

### 1.1 试卷信息

当前字段：

- 标题
- 副标题
- 考试时长
- 注意事项

建议：

- `标题` 必填。
- `副标题` 可选。
- `考试时长` 必填。
- `注意事项` 可选。

副标题不是必填项，它是标题下面的一行补充说明。学校试卷里常见内容包括：

- `2026 学年第二学期`
- `期中测试`
- `期末模拟卷`
- `A 卷`
- `满分 100 分`
- `闭卷考试`

建议把副标题 placeholder 改得更老师化：

`例如：2026 学年第二学期 · 期中测试 · 满分100分`

如果觉得“副标题”这个词不够直观，可以改成：

- `标题下说明`
- `试卷说明`

### 1.2 选题方式

保留当前两种方式：

- 手工选题
- 随机选题

手工选题用于老师精确挑题。随机选题用于按题型、难度、数量快速组卷。

### 1.3 已选题目区

“已选题目”区域建议承担两件事：

1. 展示已选题目列表。
2. 按题型批量设置分值与规则。

这个区域的顺序建议为：

1. 卡片标题：`已选题目  3题  16分`
2. 题型分值与规则
3. 已选题目表格

### 1.4 题型分值与规则

多选题得分规则不放在“页面格式”里。它应该放在第 1 步“已选题目”表格上方，也就是按题型批量配置的位置。

原因：

- 多选题得分规则属于评分规则，不属于页面版式。
- 老师选了什么题型，这里就展示什么题型的批量设置。
- 这里修改的是一类题型的分值和规则，而不是某一道题。
- 表格里的单题分值继续保留，作为个别题目的细调入口。

推荐命名：`题型分值与规则`

展示规则：

| 已选题型 | 展示内容 |
| --- | --- |
| 简答题 | 简答题：每题分值 |
| 多选题 | 多选题：每题分值 + 得分规则 |
| 单选题 | 单选题：每题分值 |
| 判断题 | 判断题：每题分值 |
| 填空题 | 填空题：每题分值 |

如果某个题型没有被选中，就不显示对应配置。

示例：

| 题型分值与规则 |
| --- |
| 简答题　共 1 题　每题 8 分 |
| 多选题　共 2 题　每题 4 分　得分规则：少选得部分分，多选/错选不得分 |

### 1.5 多选题得分规则

多选题额外需要老师选择得分规则，也允许老师自定义。

| 选项 | 说明 | 适合场景 |
| --- | --- | --- |
| 全对才得分 | 全部选对得满分，少选、多选、错选均不得分 | 严格机考或简单规则 |
| 少选得部分分 | 少选得相应分，多选、错选不得分 | 推荐默认，学校考试常用 |
| 自定义规则 | 老师自己输入规则说明 | 特殊考试或学校自定义规则 |

推荐默认值：

`少选得部分分，多选、错选不得分`

打印到试卷上的建议效果：

`二、多项选择题（共 2 题，共 8 分）`

`评分说明：少选得相应分，多选、错选不得分。`

推荐把评分说明单独成行，这样更清楚，也方便自定义长说明。

### 1.6 分值同步逻辑

第一版推荐简单处理：

- 修改某一题型的“每题分值”时，直接批量更新该题型下所有题目的分值。
- 表格内单题分值仍然可单独修改。
- 暂时不做“已单独设置”标记。

后续可以增强：

- 如果某题被单独改过，显示 `已单独设置`。
- 提供 `同步到该题型全部题目` 操作。

### 1.7 数据结构建议

前端可以维护按题型聚合的配置：

```json
{
  "typeScoreRules": {
    "short_answer": {
      "scorePerQuestion": 8
    },
    "multiple_choice": {
      "scorePerQuestion": 4,
      "scoringRule": "partial",
      "customScoringRule": ""
    }
  }
}
```

构建试卷请求时：

- 每道题仍然带自己的最终分值。
- 多选题得分规则作为试卷规则或题型规则传给后端。
- Word 渲染时把多选题规则写入对应题型说明。

## 2. 页面格式

### 2.1 页面格式区职责

页面格式只负责排版相关配置：

- 生成模板
- 纸张
- 方向
- 栏数
- 栏距
- 装订线
- 页边距
- 学生信息栏
- 字号

不放多选题得分规则。

### 2.2 左侧页面格式面板 UI 改造

当前左侧“页面格式”面板的问题主要是信息密度太挤、控件横向硬排、标签容易换行。尤其在预览页左侧窄栏里，`纸张`、`方向`、`栏数`、`栏距`、`装订线` 同一行展示时，标签会被挤成多行。

建议改成“格式控制面板”，按老师调整试卷时的思路分组：

1. 模板
2. 纸张与版式
3. 学生信息栏
4. 字号
5. 操作

### 2.3 控件规划表

| 区块 | 控件 | 推荐形式 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 模板 | 生成模式 | 分段按钮 | 标准模板 | 可选：标准模板 / 简洁模板。不要叫“源码模板”，老师不容易理解 |
| 纸张与版式 | 纸张 | 下拉框 | A3 | A3 / A4 |
| 纸张与版式 | 方向 | 下拉框 | 横向 | 横向 / 纵向 |
| 纸张与版式 | 栏数 | 下拉框 | 双栏 | 单栏 / 双栏 |
| 纸张与版式 | 栏距 | 数字输入 | 0.75 cm | 前端展示 cm，后端可继续转 twips |
| 纸张与版式 | 装订线 | 开关 | 启用 | 开关旁显示“启用装订线” |
| 纸张与版式 | 页边距 | 下拉框 | 源码装订线 | 后续可改成：标准 / 宽松 / 紧凑 |
| 学生信息栏 | 显示学生信息栏 | 开关 | 启用 | 不作为必填 |
| 学生信息栏 | 字段 | 多选勾选 | 学校、班级、姓名、学号 | 年级可选 |
| 学生信息栏 | 预览 | 只读预览 | 学校____ 班级____ 姓名____ 学号____ | 让老师马上知道卷头长什么样 |
| 字号 | 标题字号 | 数字输入 | 50 半磅 | 可在旁边显示约等于 25 磅 |
| 字号 | 副标题字号 | 数字输入 | 24 半磅 | 约等于 12 磅 |
| 字号 | 正文字号 | 数字输入 | 21 半磅 | 约等于 10.5 磅 |
| 操作 | 恢复默认 | 次按钮 | - | 放顶部右侧或底部 |
| 操作 | 应用并重新生成预览 | 主按钮 | - | 放左侧面板底部，方便调完立刻看 |

### 2.4 左侧面板示意

| 左侧格式控制面板 |
| --- |
| **模板** |
| 标准模板 / 简洁模板 |
| **纸张与版式** |
| 纸张 A3 ｜ 方向 横向 |
| 栏数 双栏 ｜ 栏距 0.75 cm |
| 装订线 开启 |
| 页边距 标准装订线 |
| **学生信息栏** |
| 显示学生信息栏 开启 |
| 学校 勾选　班级 勾选　姓名 勾选　学号 勾选　年级 不勾选 |
| 预览：学校____ 班级____ 姓名____ 学号____ |
| **字号** |
| 标题字号 50 ｜ 副标题字号 24 |
| 正文字号 21 |
| [恢复默认] [应用并重新生成预览] |

设计原则：

- 左侧窄栏内每行最多放 2 个主要控件。
- 不让标签被挤成单字换行。
- `twips` 不直接作为主标签展示，尽量用 `cm` 或中文说明降低理解成本。
- `生成模式` 不和纸张、方向平级挤在一起，改成顶部模板选择。
- 面板底部放 `应用并重新生成预览`，让老师调完后能马上看到右侧变化。

### 2.5 学生信息栏

本系统只做学校试卷场景，因此页眉信息不需要做多行业模板，也不建议保留一个让老师自由输入的大文本框。

推荐改成固定的“学生信息栏”配置：

- 开关：`显示学生信息栏`
- 字段勾选：
  - `学校`
  - `年级`
  - `班级`
  - `姓名`
  - `学号`
- 默认勾选：`学校`、`班级`、`姓名`、`学号`
- 可选勾选：`年级`
- 预览文本：`学校________  班级________  姓名________  学号________`

这项不应作为必填项。老师生成的是试卷模板，这些信息通常是留给学生考试时填写的，不是老师现在就要填完整内容。

第一阶段为了改动小：

- 前端使用结构化控件。
- 请求里仍然传最终 `headerInfo` 字符串。
- 后端 Word 模板暂时不需要大改。

后续可扩展：

- `准考证号`
- `座位号`
- `考场`

## 3. 预览与确认

### 3.1 预览页内直接调格式

在“预览与确认”页面内，把格式设置区变成可直接操作的调参面板：

- 用户不需要返回“页面格式”步骤。
- 修改纸张、方向、标题字号、副标题字号、正文字号、栏数、栏距、装订线、页边距等参数后，可以直接重新生成右侧预览。
- 预览区明确告诉用户当前预览是否已经和左侧参数一致。
- 避免用户误以为已经保存了未重新生成的预览。

推荐继续沿用当前布局：

- 左侧：`ExamPaperFormatPanel`
- 右侧：`ExamPaperPreview`

### 3.2 预览状态设计

| 状态 | 含义 | 用户看到 |
| --- | --- | --- |
| `empty` | 还没有生成预览 | 空状态，提示先生成预览 |
| `loading` | 正在生成新预览 | 加载态，禁用保存 |
| `fresh` | 当前预览和最新参数一致 | 可确认保存 |
| `dirty` | 参数变了，预览不是最新 | 警告提示，禁用保存 |
| `error` | 生成失败 | 错误卡片 + 重试按钮 |

当前代码里已经有 `previewLoading`、`previewError`、`preview`、`previewDirty`，可以继续沿用这些状态。

### 3.3 参数变化后的交互

当用户修改格式参数后：

- 右侧 PDF 不立即被当作最新结果。
- 页面显示提示：`格式参数已变化，请重新生成预览。`
- “确认生成并保存”按钮保持禁用，直到重新生成成功。

### 3.4 重新生成入口

在预览卡片顶部保留按钮：

- 有预览时：`重新生成预览`
- 无预览时：`生成预览`

左侧格式面板底部也可以加一个主按钮：

- `应用并重新生成预览`

第一阶段建议手动点击重新生成。真实 PDF 预览依赖后端 Word 生成和 LibreOffice 转换，自动刷新容易带来频繁请求、排队和旧结果覆盖问题。

### 3.5 浏览器 PDF 预览增强

当前预览使用浏览器内置 PDF 能力嵌入页面。它可以显示真实 PDF，但在卡片内查看 A3 横向试卷时，会出现两个体验问题：

- 缺少明显的 `全屏查看` 按钮。
- 点击 PDF 工具栏自带的放大/缩小后，内容固定在局部位置，不方便拖动查看。

本阶段不做自研 PDF.js 预览器，先增强浏览器 PDF 预览体验。

第一批目标：

| 需求 | 方案 |
| --- | --- |
| 全屏查看 | 在预览卡片顶部增加明显按钮：`全屏查看` |
| 新窗口查看 | 把当前文字链接改成按钮：`新窗口打开` |
| 不全屏时放大后能移动 | PDF 外层容器允许横向和纵向滚动 |
| 拖动查看 | 给 PDF 容器增加“按住拖动滚动”的交互 |
| 保留浏览器 PDF 工具栏 | 继续使用当前内嵌 PDF，不引入 PDF.js |

预览卡片顶部按钮区：

- `全屏查看`
- `新窗口打开`
- `重新生成预览`

全屏查看方案：

- 弹窗宽度：`96vw`
- 弹窗高度：`92vh`
- PDF 区域高度：`calc(92vh - 80px)`
- 保留浏览器 PDF 工具栏
- 支持滚动查看

内嵌查看滚动方案：

- PDF 外层容器 `overflow: auto`
- 固定预览高度
- 横向和纵向都允许滚动
- 鼠标样式默认 `grab`，拖动中 `grabbing`

注意：浏览器内置 PDF 插件可能会拦截一部分鼠标事件，所以拖动查看不一定在所有浏览器里完全稳定。至少要保证外层滚动条可用；全屏查看用于解决大多数看不清的问题。

### 3.6 预览失败可见反馈

当前问题：

`ExamPaperCreate.jsx` 里预览失败后只调用 `setPreviewError(error)`。但错误展示组件在第 3 步才渲染，而生成成功前不会跳到第 3 步，所以用户会感觉点击后没有反馈。

建议：

- 失败时直接补 `message.error(...)`。
- 或者失败时也切到预览页，显示错误卡片和重试按钮。
- 这项应作为最高优先级，因为它直接影响用户是否理解系统正在失败。

## 4. 后端稳定性

### 4.1 LibreOffice 启动期自检

当前 `LibreOfficePreviewConverter.java` 只有在真正调用 `soffice` 时才发现 LibreOffice 不可用，失败后再抛通用错误。

建议：

- 应用启动时检查 `soffice-path` 是否存在且可执行。
- 如果不可用，启动日志明确提示“真实预览不可用”。
- 后续可以接入管理后台、健康检查或预览能力接口。

### 4.2 Windows 默认路径候选

当前 `resolveSofficePath` 默认候选更偏 macOS/Linux。开发环境是 Windows 时，应该补充常见 Windows 安装路径。

建议增加：

- `C:\Program Files\LibreOffice\program\soffice.exe`
- `C:\Program Files (x86)\LibreOffice\program\soffice.exe`

### 4.3 保留 LibreOffice 失败输出

当前 LibreOffice 转换时丢弃 stdout/stderr，排错成本较高。

建议：

- 失败时收集并打印关键输出片段。
- 帮助定位缺字体、路径错误、权限问题、转换失败等原因。

### 4.4 预览能力接口

前端不应该靠报错猜测后端是否具备预览能力。建议增加：

`GET /api/exam/papers/preview/capabilities`

返回示例：

```json
{
  "realPdfPreviewEnabled": true,
  "converter": "LibreOffice",
  "message": "真实 Word PDF 预览可用"
}
```

前端据此显示：

- 真实预览已启用
- LibreOffice 未配置
- 当前只能使用结构预览

## 5. 后续增强

### 5.1 快速结构预览

当 LibreOffice 不可用时，不要让整个预览入口完全失败。可以允许用户查看“快速 HTML 预览”或“结构预览”，同时把“精确 PDF 预览”标记为不可用。

### 5.2 自研 PDF.js 预览器

当前先不做自研 PDF.js。后续如果浏览器 PDF 的交互仍不能满足审卷需求，再考虑自研预览器。

可支持：

- 放大 / 缩小
- 适宽 / 适页
- 上一页 / 下一页
- 页码输入
- 缩略图
- 题号定位
- 批注圈改

### 5.3 统一错误码和用户提示语

题库生成和试卷生成都应统一成：

- 错误码
- 用户提示
- 排查建议
- 是否可重试

这样可以避免一部分错误只有技术语义，另一部分错误又变成 silent fail。

## 6. 测试计划

### 6.1 前端测试

建议覆盖：

- 预览失败时一定有可见反馈。
- 参数变化后预览进入 dirty 状态。
- dirty 状态不能确认保存。
- 点击重新生成后使用最新表单参数。
- 按题型批量修改分值后，对应题型题目分值被更新。
- 多选题自定义得分规则能进入预览请求。

### 6.2 后端测试

建议覆盖：

- Windows 下 `soffice.exe` 路径解析。
- LibreOffice 缺失时返回稳定错误。
- 转换失败时日志包含关键输出。
- 多选题得分规则能渲染到题型说明。

## 7. 推荐实施顺序

1. 预览失败可见反馈，先修“点了没反应”。
2. 选题页增加“题型分值与规则”，支持多选题得分规则。
3. 左侧页面格式面板 UI 改造。
4. 学生信息栏替代自由页眉输入。
5. 预览页内调格式 + dirty 状态提示。
6. 浏览器 PDF 预览增强：全屏查看、新窗口按钮、滚动容器。
7. Windows 默认 LibreOffice 路径候选。
8. LibreOffice 启动期自检。
9. 预览能力接口。
10. 快速结构预览或自研 PDF.js 预览器。

如果只选 3 个最值的改动：

1. 修前端“点了没反应”。
2. 给后端加 LibreOffice 启动自检和 Windows 默认路径候选。
3. 选题页增加按题型分值和多选题得分规则。

## 8. 验收标准

- 老师可以在“已选题目”区域按题型批量改分值。
- 选中多选题后，可以设置多选题得分规则或自定义规则。
- 多选题得分规则能显示在生成的试卷预览中。
- 页面格式区不再承载评分规则，只处理版式。
- 学生信息栏不必填，默认生成留空线。
- 用户进入预览页后，可以直接修改纸张、方向、字号、栏距、栏数。
- 修改格式后页面不跳转、不丢失当前题目和配置。
- 修改格式后右侧明确提示预览已过期。
- 点击重新生成后，右侧 PDF 使用最新参数刷新。
- 未重新生成最新预览时，不能确认保存。
- 预览失败时，用户能看到明确错误提示和重试入口。
- PDF 预览区有明显的全屏查看和新窗口打开入口。
