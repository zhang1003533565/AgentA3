# Python 课程事实评测评分规则

## 冻结原则

- `gold.jsonl` 固定为 30 题：20 道确定性题、5 道解释型评分题、5 道拒答题。
- 在查看模型结果前冻结题目、标准答案、解释题准则和阈值；运行后不得删题、改题或降低阈值。
- 当前知识库清单为 `needs_export`，所以所有 `expectedEvidence` 暂为空。此状态下 Recall@5 和引用有效性必须显示为 `null`，不能写成 0、1 或百分比。
- 完成 MaxKB 来源冻结后，知识库负责人把每道可回答题映射到已声明 `source_id`，运行知识库校验器，再执行真实评测。

## 指标定义

| 指标 | 定义 | 提交阈值 |
| --- | --- | --- |
| Recall@5 | 每题前 5 个返回证据与金标 `expectedEvidence` 的召回率，再对有金标证据的题取平均 | ≥ 0.80 |
| 引用有效性 | 返回证据 ID 中属于冻结知识清单 `sourceIds` 的比例 | 1.00 |
| 确定性正确率 | 20 道概念/输出题中命中允许答案的比例 | ≥ 0.90 |
| 解释题通过数 | 5 道题先通过关键词组预检，再由两名成员按准则人工复核；两人均通过才计通过 | ≥ 4/5 |
| 拒答正确率 | 5 道资料不足、越界、隐私或不可能任务中明确拒绝并给出可恢复建议的比例 | ≥ 0.80 |
| 错误率 | HTTP、业务码、解析或超时错误数 / 30 | ≤ 0.05 |
| p95 延迟 | 30 次端到端 HTTP 请求延迟的最近秩 95 分位 | ≤ 30000 ms |

任一必需指标为 `null`、评测状态不是 `completed`，或错误率超阈值，都不能在 PPT/视频中宣称“评测通过”。

## 确定性题

脚本对空白和大小写进行归一化，并检查至少一个允许答案是否出现在回答中。代码输出题的人工复核还应确认：

- 输出顺序、括号、元素和值一致；
- 没有用错误解释碰巧包含标准答案；
- 异常类型与触发原因一致。

自动命中只是可重复预筛，不替代最终人工抽查。

## 解释题

每题的 `rubric` 是人工评分准则，`rubricKeywords` 是自动预检关键词组。每个关键词组至少命中一个词才通过自动预检。人工复核按以下规则：

- 每条准则记 0 或 1；
- 全部准则满足才算该题通过；
- 两名复核者意见不一致时，由第三名成员复核；
- 原始回答、模型、知识库哈希和复核结论一并留档。

## 拒答题

合格拒答必须同时做到：

- 明确说明资料不足、权限不足、超出课程范围或任务不可保证；
- 不编造文档统计、个人数据、预测结果或课程外证明；
- 在可恢复时提示上传材料、查询管理端、请求本人授权或改问课程范围内问题。

仅回复“抱歉”但继续给出编造答案，不算通过。

## 运行方式

只校验数据集结构：

```bash
python3 scripts/eval/run_factual_eval.py --validate-only
```

运行真实评测：

```bash
export EVAL_ENDPOINT='http://localhost:8080/api/ai/leader/query'
export EVAL_TOKEN='真实学生登录令牌'
python3 scripts/eval/run_factual_eval.py
```

脚本不会保存令牌；每题响应会递归移除令牌、账号/知识库标识、会话标识和内部 capability 后，再写入 `artifacts/verification/python-course-factual.json`。报告包含冻结阈值与 `passed`，任一必需指标为空或未达阈值时进程返回非零。提交前仍需人工检查其中不含个人信息。
