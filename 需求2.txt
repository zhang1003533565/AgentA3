项目需求文档：校园课程学习模块 - 小程序端开发（极简完成态）
1. 阶段目标与约束
目标：为小程序端（mini_program_app/subpackage_learning）实现课程学习与进度追踪功能。学生可查看课程章节、阅读/观看资料，并通过手动点击按钮标记资料为“已完成”。

核心约束（简单优先）：

判定逻辑：完全基于用户主观点击“标记完成”。不检测视频播放时长、不检测文档翻页、不做任何防刷/防作弊校验。

数据依赖：后端 AppProgressController 已提供 GET /api/app/progress/course/{courseId}（课程级进度数据，含全部章节+资料+状态）和 POST /api/app/progress/material/report（进度上报）。

⚠️ 缺少一个关键端点：POST /api/app/progress/material/complete（手动标记资料完成），需后端先行补充（在后端 AppProgressController 新增方法 + MaterialProgressService 新增 complete 方法），实现后小程序端才可对接。

小程序端只负责调用接口和 UI 渲染，不修改任何后端代码（上述 complete 端点也由后端单独补充，不在小程序端实现范围内）。

状态定义：status 字段为 0（未开始）或 2（已完成）。忽略 watch_seconds 字段（或置为 0）。

2. 后端接口契约（实际接口与待补充端点）

2.1 已实现接口（可直接对接）

接口 1：GET /api/app/progress/course/{courseId}
  用途：获取课程下全部章节 + 每章嵌套的资料列表 + 当前用户的学习状态
  入参：路径参数 courseId
  出参（Result<CourseProgressView>）：
    data.courseId          — 课程ID
    data.percent           — 课程总进度百分比
    data.totalCount        — 课程资料总数
    data.completedCount    — 已完成的资料数
    data.chapters[]        — 章节列表，每项含：
      .chapterId            — 章节ID
      .title                — 章节标题
      .totalCount           — 该章节资料总数
      .completedCount       — 该章节已完成资料数
      .percent              — 该章节进度百分比（0-100）
      .materials[]          — 该章节的资料列表，每项含：
        .materialId         — 资料ID
        .name               — 文件名（映射为前端展示的 fileName）
        .url                — 文件URL（映射为前端展示的 fileUrl）
        .type               — 扩展名如 mp4/pdf（映射为 fileType）
        .durationSeconds    — 时长/页数（当前版本默认 0，可忽略）
        .watchSeconds       — 已观看秒数（可忽略）
        .status             — 0=未开始 1=学习中 2=已完成 ★ 已包含状态，无需二次请求

  说明：此接口一次性返回课程全部章节+资料+状态，小程序端可直接用单次请求完成首页和详情页的数据加载，无需两阶段请求。字段名与需求原文略有差异（name/url/type vs fileName/fileUrl/fileType），小程序端封装 API 时做一层字段映射即可。

2.2 需后端补充的端点（阻塞小程序"标记完成"功能）

接口 2：POST /api/app/progress/material/complete  ← ⚠️ 当前不存在，需后端先行实现
  用途：用户手动点击"标记为已完成"，将某资料状态直接置为 2（已完成），并检测章节是否全完成
  入参：Body { "materialId": 123 }
  出参：{ "chapterCompleted": true/false, "chapterId": 456 }
  后端实现指引：
    - 在 AppProgressController 新增 @PostMapping("/material/complete") 方法
    - 在 MaterialProgressService 新增 complete(userId, materialId) 方法：
      1) 查 learning_material_progress，将 status 设为 2（已完成）
      2) 调用已有的 syncChapterCompletion() 检测章节是否全完成
      3) 返回 Map/Record 含 chapterCompleted 和 chapterId
    - 该端点放在 POST /api/app/progress/material/report 旁边，复用已有 userId 提取逻辑

2.3 已存在但不直接使用的接口（供参考）

POST /api/app/progress/material/report — 进度上报（需 watchSeconds），用于视频/音频自动上报场景，手动标记完成场景使用上面的 /complete 端点即可，无需调用此接口。

3. 页面 UI 与交互设计（极简版）

数据加载策略：由于 GET /api/app/progress/course/{courseId} 一次性返回课程所有章节嵌套资料+状态，小程序端只需调用一次即可获取首页和详情页所需的全部数据。页面间通过导航参数传递 chapterId，详情页从已缓存的数据中筛选对应章节渲染。

页面 A：课程学习首页（章节列表）

展示内容：课程标题 + 课程总进度（percent%）+ 所有章节列表。
每张章节卡片展示：章节标题 + 进度文字（如"已完成 2/5 个资料"）+ 进度条（percent%）。
交互：点击某个章节，跳转至"章节详情页"，传递 courseId + chapterId。

页面 B：章节详情页（资料列表 + 标记完成） —— 核心交互

布局：
  顶部：显示章节标题 + 进度概览（如"已完成 2/5 个资料"）。
  资料列表：展示该章节下所有资料（视频、PDF、PPT 等），每条显示：
    - 文件名（name 字段）
    - 文件类型标签（type 字段，如 [视频] [PDF] [PPT]）
    - 状态为 0（未开始/学习中）：显示"标记为已完成"按钮（主色调）
    - 状态为 2（已完成）：显示"已完成"标签（灰色禁用，不可点击）
  视频/文档查看：点击资料卡片本身（非按钮区域）可预览/下载文件，沿用项目现有 campusCourseDetail.vue 中的 openResource 逻辑（uni.downloadFile → uni.openDocument）。

4. 核心业务逻辑（前端实现细则）

逻辑 1：资料"标记完成"操作流程
  1) 用户点击资料卡片上的"标记为已完成"按钮。
  2) 前端调用 POST /api/app/progress/material/complete，传入 { materialId }。
  3) 等待后端返回：
     若成功：
       - 将该资料在当前列表中的 status 更新为 2，按钮变为"已完成"状态。
       - 重新计算并更新页面顶部进度统计（如 completedCount / totalCount）。
       - 若返回 chapterCompleted: true，弹窗提示"恭喜你完成本章节！"。
     若失败：展示错误提示（如"网络异常，请重试"），恢复按钮可点击状态。

逻辑 2：章节进度计算
  后端 GET /api/app/progress/course/{courseId} 已在 ChapterProgressView 中返回 percent、completedCount、totalCount，前端直接使用即可。标记完成后，前端本地更新对应资料的 status 并重新计算：
    chapterPercent = (status===2 的资料数) / (总资料数) * 100

逻辑 3：进入页面时的数据加载
  首页（页面 A）onLoad 时：
    - 获取 courseId（从导航参数）。
    - 调用 getCourseProgress(courseId)（封装 GET /api/app/progress/course/{courseId}）。
    - 将返回的 chapters 数组存储到 data 中用于渲染首页章节列表。
  详情页（页面 B）onLoad 时：
    - 获取 courseId + chapterId（从导航参数）。
    - 再次调用 getCourseProgress(courseId)，从返回的 chapters[] 中 find 匹配 chapterId 的章节，提取其 materials 赋值到 data。
    - （推荐二次请求而非跨页面传参：请求量极小，逻辑自包含，无需全局状态管理或页面栈传参的复杂度。）

5. 边界情况与健全性处理（防崩溃）
场景	处理方式
章节未关联任何资料	列表为空时，显示占位提示：“本章节暂无学习资料，请联系管理员。”，并隐藏“标记完成”按钮。
用户重复点击“标记完成”	点击后立即禁用该按钮（disabled=true），防止重复提交。待接口返回后再恢复或置为已完成状态。
接口报错（500/超时）	弹窗提示“操作失败，请重试”，并恢复按钮可点击状态。
打开资料文件失败	捕获 wx.downloadFile 或 web-view 的加载错误，提示“文件打开失败，请检查网络”。
6. 需要生成/修改的代码文件清单

6.0 前置条件：后端补充端点
  在 AppBackend 中新增 POST /api/app/progress/material/complete（见 §2.2），编译验证通过后再开始小程序端开发。

6.1 API 封装（mini_program_app/api/learning.js 末尾追加，不动已有 Python 相关方法）：
  - getCourseProgress(courseId)：GET /api/app/progress/course/{courseId}，返回 data（CourseProgressView）。
    后端字段名为 name/url/type，模板中直接使用 material.name / material.url / material.type 即可，无需额外映射。
  - markMaterialComplete(materialId)：POST /api/app/progress/material/complete，Body { materialId }，
    返回 { chapterCompleted, chapterId }。

6.2 页面改造（mini_program_app/subpackage_learning/campusCourseDetail/campusCourseDetail.vue）：
  这是小程序端唯一需要大幅修改的文件（已是单文件组件 .vue，含 template/script/style）：
  - data：新增 materials[]（当前章节资料列表）、chapterProgress（{ completedCount, totalCount, percent }）、completingId（防重复提交）。
  - onLoad：获取 courseId + chapterId，调用 getCourseProgress(courseId)，从返回的 chapters[] 中 find 匹配 chapterId 的章节，提取其 materials 赋值到 data。
  - template：在章节展开区域（chapter-body）内，替代现有的 old resourceUrl 单文件展示，改为 v-for 遍历 materials 渲染资料卡片列表。
    每条卡片包含：文件图标/类型标签 + name（fileName）+ 类型 tag（type/fileType 映射为中文标签）+ "标记为已完成"按钮（status !== 2 时显示）或"已完成"标签（status === 2）。
    顶部显示进度文字："已完成 {{ completedCount }}/{{ totalCount }} 个资料"。
  - methods：
    - handleMarkComplete(material)：调 markMaterialComplete(material.materialId)，成功后更新本地 materials 中该条 status=2，重新计算 chapterProgress；若返回 chapterCompleted=true 则 uni.showModal 弹恭喜提示。
    - openMaterial(material)：沿用现有 openResource 逻辑，用 material.url 替换原 chapter.resourceUrl。
  - style：新增资料卡片、完成按钮、类型标签、进度统计的样式（沿用项目现有 SCSS 变量和设计风格）。

6.3 首页集成（可选）：
  - 可修改 campusCourseDetail.vue 本身的章节列表渲染（即页面 A 的章节卡片区域），直接使用 getCourseProgress 返回的 chapters[] 数据，展示每章的 completedCount/totalCount 和进度条。
  - 不需要额外创建新页面，在当前 vue 文件的 template 中扩展章节卡片内容即可（章节卡片已存在，只需增加进度展示字段）。

7. 验收标准
☑ 进入章节详情页，能正确显示该章节所有资料列表。
☑ 点击"标记为已完成"，按钮变为"已完成"状态且不可再次点击。
☑ 页面顶部的进度统计（如 1/3）能正确更新。
☑ 当章节最后一个资料被标记完成时，弹出"恭喜完成本章节"的提示。
☑ 刷新页面后，已完成的资料状态依然保持"已完成"。
☑ 空章节（无资料）显示友好的占位提示，不报错崩溃。
