\# Project Agent Rules





\## Project Overview



This project is a campus second-hand marketplace application.



Purpose:



Provide a simple platform for university students to:



\- Discover second-hand items

\- Publish unused items

\- Communicate with other students

\- Complete offline transactions





\## Technology Stack



Frontend:



\- UniApp

\- Vue3

\- Vite





Backend:



\- Spring Boot

\- MySQL

\- Redis





\---



\# Development Principles



\## Understand Before Changing



Before modifying code:



1\. Locate the existing implementation.

2\. Understand current behavior.

3\. Check related components.

4\. Make the smallest effective change.





Do not immediately rewrite existing code.





\---



\# Existing Product Protection



This is an existing application.



Preserve:



\- Existing user flows

\- Existing navigation

\- Existing business logic

\- Existing components





Avoid:



\- Unnecessary refactoring

\- Duplicate implementations

\- Changing unrelated files





When the user explicitly requests:



\- New features

\- Refactoring

\- Architecture changes



Follow the request carefully.





\---



\# UI Direction



Overall style:



\- Minimal

\- Clean

\- Modern

\- Lightweight





Preferred:



\- Light gray background

\- White surfaces

\- Dark text

\- Low saturation blue-gray accent

\- Linear icons





Avoid:



\- Emoji icons

\- Excessive cards

\- Strong gradients

\- Heavy shadows

\- AI-generated visual style





\---



\# Feature Rules



Do not add new features unless explicitly requested.



Do not invent:



\- User data

\- School information

\- Statistics

\- Business states





Only use:



\- Existing data

\- User-provided requirements





\---



\# Frontend Rules



Before creating components:



Check:



\- Existing components

\- Existing styles

\- Existing patterns





Prefer:



\- Component reuse

\- Consistent design

\- Minimal changes





Avoid:



\- Copying similar components

\- Creating temporary UI patches





\---



\# Animation Rules



Animations should have a purpose.



Prefer:



\- Smooth transitions

\- Natural movement

\- Existing animation patterns





Avoid:



\- Random zoom animations

\- Excessive effects

\- Duplicate animation systems





\---



\# Verification



After changes:



Check:



\- Related pages

\- User flow

\- Console errors

\- Visual consistency





Report:



1\. Changed files

2\. Reason for changes

3\. Possible impact

4\. Verification result
